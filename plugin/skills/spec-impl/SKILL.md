# 4단계: 구현

대상: $ARGUMENTS

## 현재 스펙
`specs/*/` 문서들의 맨 위 상태 줄(`> 상태: …`)과 tasks.md의 체크박스로 각 스펙의 단계를 확인한다.

## 절차
1. **대상 고르기** — 인자로 받은 기능을 쓴다. 인자가 없으면 위 목록에서 작업 목록이 승인됐고 남은 작업이 있는 스펙을 고른다. 후보가 여럿이면 묻는다.
2. **관문 확인** — `specs/<기능>/tasks.md`의 상태가 `승인됨`이 아니면 멈추고 "작업 목록이 아직 승인되지 않았습니다. `/spec-tasks`로 마무리해 주세요."라고 안내한다.
3. **작업 고르기** — 인자로 받은 번호, 없으면 체크되지 않은 첫 작업.
4. **읽기** — requirements.md, design.md, tasks.md를 전부 읽고, 그 작업이 건드리는 코드를 읽는다.
5. **구현** — 그 작업 하나만 구현한다. 설계에 적힌 파일·인터페이스를 따른다.
   - 다음 작업의 일을 미리 하지 않는다.
   - 설계대로는 안 되거나 설계가 틀렸다는 것을 알게 되면 멈춘다. 이유와 design.md 수정안을 보여주고 `AskUserQuestion`으로 묻는다: "수정안대로 design.md 고치고 진행" · "여기서 멈춤"(다른 방법은 기타 입력칸). 승인되면 design.md를 고친 뒤 이어간다.
6. **확인** — 작업의 완료 조건을 실제로 확인한다(테스트 실행 등). 실패하면 고친다. 고칠 수 없으면 체크하지 말고 실패 내용과 원인 가설을 보고한다.
7. **체크** — 완료 조건이 확인되면 tasks.md의 그 작업을 `- [x]`로 바꾼다. `.claude-memory/`가 있으면 `progress.md`에 기록한다.
8. **보고** — 바뀐 파일, 확인 결과(명령과 결과), 다음 작업을 짧게 보고하고 `AskUserQuestion`으로 묻는다: "다음 작업 진행" · "남은 작업 전부 진행" · "여기서 멈춤". 대화로 "계속"이라고 해도 다음 작업을 한다.
   - "전부"(박스 또는 대화)를 골랐으면 묻지 않고 다음 작업으로 계속 넘어간다. 단, 확인이 실패하거나 설계를 바꿔야 하면 그때 멈추고 묻는다.
9. **마무리** — 모든 작업이 체크되면 requirements.md의 인수 조건을 하나씩 대조해 충족 여부를 표로 보고한다.

## 규칙
- 완료 조건을 확인하지 않은 작업은 체크하지 않는다.
- 스펙(요구사항·설계)과 다르게 구현하지 않는다. 달라져야 하면 먼저 문서를 고치고 승인받는다.
